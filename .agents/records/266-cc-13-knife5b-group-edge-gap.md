## 目标与范围

**一处修正**：`resolveCcHeightGroups` / `resolveCcWidthGroups` 里，**新建**某落脚处的组 / 队列时的 `edgeGap`，
从**字面 0** 改为**该落脚处在定义表里声明的边距**（与"谁在场"无关）。

- 竖向：状态区（`cc-surface:bottom`）⇒ 边距字段 `ccMarginBottom`（默认 15px）；
- 横向：同口径取 `layout.x.gap`（今天全行缺省 ⇒ 0，读数不变，钉一条断言防将来漂移）；
- **等价性要求**：内置行在场时"在场行取 max"与本表声明值逐位相等 ⇒ **内置件读数逐位不变**。

**不做**：不动插件件的其它计数口径（高取 max / 宽求和 / 只在报尺寸时建组）；不加实测机制；不动 CSS / 后端；不动契约与渲染层（本接续只在算式内改 `edgeGap` 的**初值来源**）。

## 方案要点

1. **边距属落脚处，不属"在场的那几件"**：落脚处键本身就是 `y.anchor:y.side` ⇒ 同一落脚处的行**同 side**
   （竖向取到同一字段）、`layout.x.gap` 声明相同 ⇒ 本表派生值与"在内置行里取 max"**逐位相等**；
   两者只在"该落脚处无任何内置件在场"时分道 —— 那正是本接续补的那一半（空态默认就是这个组合：
   内置状态件全藏在 `ccHiddenEmpty`、只剩插件件）。
2. **只改"新建"处的初值**（不是重写组级取值逻辑）：组/队列一旦建立，后续仍按原逻辑维护
   （竖向 `edgeGap` 组内取 max、横向队列 `layout.x.gap` 取 max）⇒ 内置行在场所走的路径逐字未变。
3. **缺项按 0**：`declaredVerticalEdgeGap` 只认"该落脚处声明的字段"的有限值，取不到 ⇒ 0
   （与算式既有纪律一致）；`Math.max(0, …)` 保证与旧口径（初值 0 起取 max）在负值/非法值上同向。
4. **静态派生一次**（模块加载时）：表是编译期真值，`LANDING_EDGE_FIELDS` 不随渲染/可见性变化；
   只读 `layout.y.side` / `layout.x.gap`，不读 `detachX` 等会被测试临时改写的字段（既有测试的
   `detachX` 临时声明不受影响）。
